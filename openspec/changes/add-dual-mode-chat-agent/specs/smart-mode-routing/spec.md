# smart-mode-routing 规格

## ADDED Requirements

### Requirement: 任务型消息识别
系统 SHALL 在普通对话模式下对每条用户消息进行任务/闲聊分类；判定为任务时，MUST 弹出确认卡片而非自动执行。

#### Scenario: 任务型消息触发确认卡片
- **WHEN** 用户在普通对话模式发送"帮我做一份Q3销售数据报告"
- **THEN** 系统弹出确认卡片："这看起来像一项工作，要用工作模式处理吗？"，且不自动开始执行

#### Scenario: 闲聊消息正常直答
- **WHEN** 用户在普通对话模式发送闲聊或知识型消息
- **THEN** 系统按普通对话直答，不弹卡片

### Requirement: 确认卡片携带原始消息
系统 SHALL 在用户确认切换时，将触发卡片的消息原样作为第一条任务指令带入工作模式。

#### Scenario: 确认后消息成为任务指令
- **WHEN** 用户在确认卡片上点击"切换到工作模式"
- **THEN** 系统切换到工作模式，并以该卡片对应的消息作为任务指令启动 Agent

### Requirement: 拒绝卡片回到普通对话
系统 SHALL 在用户拒绝确认卡片时，将该消息按普通对话直答处理。

#### Scenario: 用户拒绝切换
- **WHEN** 用户在确认卡片上点击"继续对话"
- **THEN** 系统留在普通对话模式，并对原消息给出 LLM 直答回复

### Requirement: 工作模式下不做路由判断
系统 SHALL 在工作模式下跳过任务/闲聊分类，所有消息直接交给 Agent。

#### Scenario: 工作模式消息直达 Agent
- **WHEN** 用户处于工作模式并发送任何消息
- **THEN** 消息直接进入 Agent 对话流，无路由环节
