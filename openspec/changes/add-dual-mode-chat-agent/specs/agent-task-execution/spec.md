# agent-task-execution 规格

## ADDED Requirements

### Requirement: Agent 工具循环执行任务
系统 SHALL 在工作模式下使用 LangGraph Agent（工具调用循环）执行用户任务，可调用进程内工具（文件生成、格式转换、渲染）与沙箱工具（代码执行）。

#### Scenario: 任务执行产出产物
- **WHEN** 用户在工作模式提交"做一份Q3销售数据报告"
- **THEN** Agent 通过工具循环完成数据处理与文档生成，产出一个可预览的产物，任务进入预览就绪状态

#### Scenario: 任务执行失败可恢复
- **WHEN** Agent 执行过程中发生不可恢复错误
- **THEN** 系统将失败原因以用户可读的形式返回对话流，任务状态标记为失败且不产生产物

### Requirement: 执行过程事件流
系统 SHALL 在 Agent 执行期间通过 SSE 向前端推送过程事件（当前步骤、工具调用、中间输出），前端实时展示。

#### Scenario: 前端实时展示工具调用
- **WHEN** Agent 正在执行任务并调用了代码执行工具
- **THEN** 前端实时显示对应的工具调用过程与状态

### Requirement: 执行中消息注入（转向）
系统 SHALL 将用户在任务执行中发送的消息排队，并在工具循环的下一个间隙注入 Agent 对话流，作为转向/追加指令影响后续执行。

#### Scenario: 执行中插话改变任务方向
- **WHEN** 任务执行中用户发送"图表改成柱状图"
- **THEN** 系统在当前工具调用完成后将该消息注入 Agent 上下文，Agent 按新要求继续执行

#### Scenario: 执行中插话不打断当前工具调用
- **WHEN** 用户在工具调用进行中插话
- **THEN** 当前工具调用正常完成，消息在下一轮循环间隙被处理

### Requirement: 任务状态机
系统 SHALL 维护任务状态机：待命 → 执行中 → 预览就绪 →（修改 → 执行中）*→ 已交付，状态变更持久化并可恢复。

#### Scenario: 服务重启后任务状态可恢复
- **WHEN** 后端在任务预览就绪状态下重启
- **THEN** 用户重新打开会话时任务状态与产物完整恢复
